# AutoLogin

A password manager for Minecraft servers that ask you to log in. It watches the
server's messages for a login prompt, shows you the saved password for that
server as clickable chat options (and in a small picker screen), and sends the
one you pick as `/login <password>` - the way you would have typed it yourself,
just without the typing.

Client-side only. Nothing is installed on the server and nothing is sent
anywhere except the one command you choose.

## What it does

1. **Detects** the prompt. Server messages are matched against a table of the
   phrases authentication plugins actually print (AuthMe, nLogin, LibreLogin,
   LoginSecurity, FastLogin, the generic "Please login with /login <password>"
   family), plus any regex you add yourself.
2. **Offers** the saved logins for that server. In chat:

   ```
   AutoLogin: mc.example.com wants you to log in
   [1] main  [2] alt  [+] add login  [x] later
   ```

   Every option is clickable, like command suggestions. `F9` or `/autologin`
   opens the same list as a screen.
3. **Sends** only after you click. The mod never sends a password on its own.
4. **Notices** when the server says "Successfully logged in!" and stops asking.

## Security model

This is worth reading once, because the mod holds passwords.

- **Passwords are encrypted at rest.** `config/autologin/accounts.vault` is
  AES-256-GCM sealed with a key derived (PBKDF2-HMAC-SHA256, 210k rounds) from
  a machine fingerprint and a random salt in `config/autologin/vault.salt`.
  The file is `chmod 600` where the OS supports it. Copy the config folder to
  another machine and the passwords will not decrypt - they will be reported as
  unreadable rather than silently replaced, and you re-enter them.
- **The key is on your machine, so this is not protection from someone using
  your computer.** It protects a synced config folder, a backup, or someone
  reading the file: none of them get the password from the bytes.
- **A password is only ever sent as a command, never as chat.** Chat is
  broadcast to the whole server; a command goes to the server alone.
- **Only authentication verbs are used.** A server can print any text it likes,
  including "please run /msg Someone &lt;your password&gt;". The verb comes from
  the message only if it is on a short allowlist (`login`, `l`, `log`, `auth`,
  `register`, ...), otherwise the rule's own command is used.
- **Passwords never enter chat history.** Clicking an option runs a *client-side*
  command (`/autologin use 1`), which triggers the send directly through the
  network handler. The password is never placed in the chat input box, so it
  cannot be recalled with the up arrow or caught in a screenshot of the input
  line. There is deliberately no `/autologin add <password>` command - adding a
  login always goes through the screen.
- **Nothing is logged.** The debug log records the rule that fired and
  `sent /login <hidden>`, never the password.

## Using it

| Action | How |
|---|---|
| Pick a saved login | Click a chat option, press `F9`, or run `/autologin` |
| Add a login | `[+] add login` in the prompt, `/autologin add`, or the picker screen |
| List saved logins | `/autologin list` |
| Remove one | `/autologin remove <label>` |
| Settings | `/autologin config`, or Mod Menu |
| Turn off for this session | `/autologin off` (`/autologin on` to bring it back) |
| Debug why a prompt was missed | `/autologin debug`, then watch the log |

Settings live in `config/autologin.json` and are generated by
[Cloth Config](https://modrinth.com/mod/cloth-config), which is required.
[Mod Menu](https://modrinth.com/mod/modmenu) is optional; without it use
`/autologin config` or `F9`.

### AuthMe 6 and native login dialogs

AuthMe 6.0.1 can ask for the password with a **native dialog** instead of a chat message
(`settings.registration.dialog.preJoin.enable` / `postJoin.enable`, on by default on
Paper 1.21.11+). A dialog is a server-driven form, not text, so AutoLogin cannot see it
and cannot fill it. If your server uses one, either turn those two options off so AuthMe
falls back to chat, or type the password once by hand.

### Custom rules

If your server prints something the built-in table misses, add a line to
**Custom rules** in the settings screen:

```
LOGIN ^Please /login <password>$
REGISTER ^/register <password>
AUTHENTICATED ^Access granted
```

`LOGIN` and `REGISTER` ask for credentials; `AUTHENTICATED` means the session is
open and the mod should stop asking. The regex is matched against the plain text
of the message, case-insensitively. Bad lines are skipped and reported in the
log, so one typo cannot break the others.

### Per-server matching

A saved login is tied to `host` or `host:port`, with `:25565` dropped, so
`MC.Example.com` and `mc.example.com:25565` are the same server. Use `*` as the
server to offer a login everywhere - useful when you use the same password on a
network, riskier everywhere else.

## Branches

One branch per Minecraft version line; CI builds every supported release from
each branch as a matrix job on [Blacksmith](https://www.blacksmith.sh) runners.

| Branch    | Minecraft line     | Java | Cloth Config | Build                |
|-----------|--------------------|------|--------------|----------------------|
| `main`    | 26.x and above     | 25   | 26.x line    | Matrix: 26.1 - 26.3  |
| `1.21.11` | 1.21.11 (legacy)   | 21   | 21.11.x      | Single version       |

## Building

The whole matrix builds from a single source tree through `-P` overrides:

```sh
./gradlew build -Pminecraft_version=26.3 -Pfabric_api_version=0.165.0+26.3 \
  -Pcloth_config_version=26.3.159 -Pmodmenu_version=21.0.0 \
  -Pminecraft_dependency="~26.3"
```

Gradle itself needs Java 25 on both branches (Loom 1.19); the mod compiles to
the version in `options.release`.

## Testing

```sh
./gradlew test              # detection, flow, vault, server keys - no client boot
./gradlew runClientGameTest # a real client, a real world, a real /login command
```

The unit suite covers the parts that are pure Java. The client gametest boots a
singleplayer world, makes the integrated server say a login prompt, checks that
the mod offered the saved login and sent nothing, picks it, and asserts that a
server-side `/login` handler received exactly the saved password. Screenshots
land in `build/run/clientGameTest/screenshots/`.
